# Versiones EXACTAS con las que se construye el ejecutable (fase 2 de
# docs/EMPAQUETADO.md).
#
# Salen del `pip freeze` del equipo donde DepthGuard funciona hoy
# (Windows, Python 3.11.9), no de "la ultima version de cada cosa". Todas
# tienen wheel precompilado para Windows + CPython 3.11, comprobado con
# `pip download --platform win_amd64 --only-binary=:all:`.
#
# Se instala SIEMPRE con --no-deps:
#
#     pip install --no-deps -r empaquetado/requirements-build.txt
#     python empaquetado/verificar_entorno.py
#
# --no-deps es deliberado. La lista ya esta completa (es un freeze), y sin
# esa bandera pip volveria a resolver dependencias por su cuenta:
#   - face-recognition declara `dlib`, y dlib-bin no cuenta como tal, asi que
#     pip intentaria COMPILAR dlib desde el codigo fuente.
#   - mediapipe arrastraria un segundo OpenCV.
# verificar_entorno.py comprueba despues que no falte nada.
#
# Diferencias con el freeze original, a proposito:
#   - Se quita opencv-python. mediapipe exige opencv-contrib-python, y los dos
#     paquetes escriben el MISMO fichero cv2/cv2.pyd: cual queda depende del
#     orden de instalacion. contrib es la misma version y contiene todo lo del
#     otro, asi que se deja solo ese.
#   - Se AGREGA setuptools (pip freeze no lo lista nunca). face_recognition_models
#     hace `from pkg_resources import ...`, y pkg_resources desaparecio en
#     setuptools 82: con una version nueva, `import face_recognition` falla y
#     no hay reconocimiento. 80.10.2 es la ultima 80.x y todavia lo trae.
#
# No se toca requirements.txt: es el que usan INSTALAR.bat / INICIAR.bat, y
# esta fase no cambia nada para quien arranca sin empaquetar.
